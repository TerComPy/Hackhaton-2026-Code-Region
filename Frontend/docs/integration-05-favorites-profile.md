Integration 05 — Real Favorites & Profile

Реализованы отдельные Pinia-состояния favorites и userProfile. Сессия и каталог сохраняют свою ответственность. Mock-избранное по-прежнему использует прежний demo store/localStorage; API-избранное хранит только серверные DTO и строковые ID.

GET /favorites загружает страницы по 20 до неполной страницы, включая дополнительный запрос после полной последней страницы. Лимита в 100 записей и выдуманного total нет. Закладки каталога, VacancySheet, страницы избранного и счётчик навигации используют общий список реальных ID. Поле is_favorite из деталей и demo store не служат источником состояния API-закладок.

SaveButton отправляет PUT/DELETE, блокирует повторные клики и фиксирует изменение только после успешного ответа. Затем получает актуальные метаданные с сервера. При ошибке мутации подтверждённое состояние сохраняется; есть сообщение и retry. При ошибке загрузки доступна повторная загрузка. Архивные вакансии остаются видимыми и удаляются; повторное добавление архивной вакансии в UI отключено.

При выходе/смене аккаунта синхронно очищаются избранное, ошибки, pending и черновики профиля; AbortController отменяет запросы. Поколение запросов защищает от применения поздних ответов аккаунта A к аккаунту B. Сервер уже мог выполнить запрос до отмены: клиентская отмена не является откатом SQL. Карточка избранного закрывается при смене аккаунта и уходе со страницы.

Профиль использует существующий GET /profile из восстановления/входа и отдельную кнопку обновления. PATCH редактирует только имя и город. Имя проверяется после trim (1–150 символов), город — до 150; пустой город отправляется как null. Есть загрузка, сохранение, ошибка и подтверждение успеха. После PATCH обновляются профиль, имя в навигации и аватар-инициал. Email, пароль и аватар не редактируются. Backend и JWT-механизм не изменялись.

Фактические результаты на локальном Express + MySQL 127.0.0.1:33316:

| Операция | HTTP / проверка |
| --- | --- |
| PUT /api/favorites/:id | 204 |
| Повторный PUT того же ID | 204, GET содержит одну запись |
| GET /api/favorites | 200, данные только текущего пользователя |
| DELETE /api/favorites/:id | 204 |
| Повторный DELETE | 204 |
| GET избранного с архивной вакансией | 200, status=archived |
| PUT архивной вакансии после удаления | 404 |
| GET /api/profile | 200 |
| PATCH имени и города | 200; GET и reload подтверждают сохранение |
| PATCH с пустым именем | 400 |
| GET /favorites и GET /profile с неверным JWT | 401 |

E2E дополнительно проверяют: двойной клик даёт один PUT; состояние закладки совпадает в каталоге и панели; избранное сохраняется после reload; пользователь B не видит избранное и город пользователя A; сетевые ошибки сохранения и PATCH не создают ложного успеха; network error GET не вызывает mock fallback; retry восстанавливает реальные данные; выход отменяет незавершённые GET избранного и PATCH профиля, поздние ответы игнорируются.

Пагинация проверена на 101 реальной MySQL-фикстуре: запросилась шестая страница и отобразились 101 уникальная вакансия с BIGINT ID вне безопасного диапазона Number. После удаления архивной записи проверены 100 результатов и обязательный запрос пустой шестой страницы. Тесты создают отдельные записи с префиксом favorites-e2e; очистка удаляет только успешно созданные ими вакансии и их связи. Seed и чужие записи не сбрасываются. Помеченные TEST FIXTURE аккаунты остаются в локальной БД, как и в существующих auth E2E.

Порт API E2E теперь можно задать через PLAYWRIGHT_API_PORT; стандартный 5190 сохранён. Для прогона использован 5261, поскольку 5190 был занят. Чужие серверы не останавливались. Тест пустого каталога с фиктивным JWT дополнен таким же фиктивным ответом защищённого GET /favorites, чтобы реальный 401 закономерно не очищал его искусственную сессию.
