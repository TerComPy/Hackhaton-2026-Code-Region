# Integration 02 — настоящая авторизация

Проверено локально 12 ноября 2026. Express :3000, отдельная MySQL Community
8.4.13 :33316, API-mode Vite proxy :5190. Backend не изменялся на этом этапе.
Исходный frontend сохранён в `.local-backup/auth-before/frontend.tar`.

Существующая форма в API-режиме вызывает register/login через общий HTTP-клиент,
затем загружает /auth/me и /profile. Успешное состояние показывается только после
загрузки обоих ответов. UUID и BIGINT остаются строками. В API-режиме пароль
8–128 символов, displayName до 150, email до 254 — в соответствии с backend.
Mock-режим сохраняет прежнюю валидацию и демонстрационное поведение.

В sessionStorage сохраняется только access-токен, ключ starter.api.accessToken.
При перезагрузке личность повторно проверяется сервером. Пароль не сохраняется,
поле очищается при отправке. localStorage для JWT не используется. Ошибки
400/401/409, сетевые ошибки и таймауты показаны в форме. Невалидная/истёкшая
сессия очищается и предлагает войти повторно. Нет refresh и продления JWT.
Выход очищает токен, профиль и пользовательское состояние, отменяет запросы;
поздние ответы не восстанавливают сессию. Серверный logout не имитируется:
ранее выданный JWT сохраняет серверную валидность до истечения/отзыва сервером.

Реальные displayName/email показаны в профиле. Навигация меняется Войти → Профиль
и обратно, включая мобильную подпись. Восстановление сессии имеет состояние
загрузки. Формы блокируют повторную отправку. Demo-профиль и demo-избранное
не читаются и не перезаписываются API-режимом. Каталог/избранное не подключались.
CSS авторизации, полноэкранная компоновка, анимация и VacancySheet не менялись
этой реализацией. Обнаруженное параллельное редактирование Perlin сохранено.

## Проверки

| Реальный запрос через proxy | HTTP |
| --- | --- |
| POST /api/auth/register, новый TEST FIXTURE аккаунт | 201 |
| POST /api/auth/register, тот же email | 409 |
| POST /api/auth/login, верный пароль длиной 8 | 200 |
| POST /api/auth/login, неверный пароль | 401 |
| POST /api/auth/login, короткий пароль | 400 |
| GET /api/auth/me, JWT | 200 |
| GET /api/profile, JWT | 200 |
| GET /api/auth/me, без JWT | 401 |
| GET /api/auth/me, невалидный сохранённый JWT | 401 |
| GET /api/ready, реальная MySQL | 200, database=ok |

E2E подтверждает перезагрузку сессии, клиентский выход и отсутствие восстановления
после выхода. Истечение проверено продвижением браузерных часов на час после
настоящего входа; серверные ответы не подменялись успехом. Сетевая ошибка и
10-секундный timeout проверены явным отказом/задержкой запроса в Playwright.
Все созданные аккаунты обозначены TEST FIXTURE, email в example.invalid.

Typecheck и build успешны. Основной Playwright: **70 passed, 38 skipped**.
Пропуски: 8 Perlin вне двух поддержанных desktop-проектов, 6 API-mode и
24 auth E2E в mock-конфигурации. Отдельно `test:api-mode`: **5 passed** —
четыре сценария auth и существующая проверка API-режима. LIVE_API=1 включал
реальные readiness-проверки во всех шести проектах.

В проверенной порции логов Express (57 строк) JWT и открытых полей password не
найдено, 20 заголовков Authorization редактированы как [Redacted]. В E2E также
проверено отсутствие пароля/JWT в console браузера и постоянном хранилище.
Логгер backend уже имеет redaction для password, password_hash, accessToken,
authorization и cookie. Секреты в отчёт не включены.

Команды из Frontend:

```powershell
npm run typecheck
npm run build
$env:PLAYWRIGHT_CHANNEL='chrome'
$env:LIVE_API='1'
npm run test:smoke -- --workers=2
npm run test:api-mode
```

API-mode тесты поднимают отдельный Vite на 5190 и требуют работающий backend.
Для ручной проверки: `$env:VITE_DATA_MODE='api'`, затем `npm run dev` и /#/account.
